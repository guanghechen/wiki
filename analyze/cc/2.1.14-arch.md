## 1. 总体架构

Claude Code 采用 **单主 Agent + 多子 Agent** 的分层架构：

```
┌───────────────────────────────────────────────────────────────────┐
│                         Claude Code CLI                           │
├───────────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │                      Main Agent Loop                        │  │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐      │  │
│  │  │ System      │  │ Message     │  │ Tool            │      │  │
│  │  │ Prompt      │─>│ Processing  │─>│ Execution       │      │  │
│  │  │ Assembly    │  │             │  │                 │      │  │
│  │  └─────────────┘  └─────────────┘  └────────┬────────┘      │  │
│  └─────────────────────────────────────────────│───────────────┘  │
│                                                │                  │
│  ┌─────────────────────────────────────────────▼───────────────┐  │
│  │                  Sub-Agents (via Task Tool)                 │  │
│  │  ┌────────┐ ┌─────────┐ ┌───────┐ ┌───────┐ ┌────────────┐  │  │
│  │  │ Bash   │ │ Explore │ │ Plan  │ │ Coder │ │  General   │  │  │
│  │  │ Agent  │ │ Agent   │ │ Agent │ │ Agent │ │  Purpose   │  │  │
│  │  └────────┘ └─────────┘ └───────┘ └───────┘ └────────────┘  │  │
│  └─────────────────────────────────────────────────────────────┘  │
├───────────────────────────────────────────────────────────────────┤
│                       External Interfaces                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────────────┐   │
│  │ Claude   │  │ File     │  │ Shell    │  │ MCP Servers      │   │
│  │ API      │  │ System   │  │ (Bash)   │  │ (Extensible)     │   │
│  └──────────┘  └──────────┘  └──────────┘  └──────────────────┘   │
└───────────────────────────────────────────────────────────────────┘
```

**核心组件**：

| 组件              | 职责                                       |
| ----------------- | ------------------------------------------ |
| Main Agent Loop   | 处理用户输入，协调工具调用，生成响应       |
| System Prompt     | 动态组合的上下文，定义 Agent 能力和行为    |
| Tool System       | 19 种内置工具，支持文件、搜索、Web、任务等 |
| Sub-Agent System  | 通过 Task 工具启动的专门化 Agent           |
| External Services | Claude API、文件系统、Shell、MCP 服务器    |

### 关键流程说明

**Step 3-5 是 Agent Loop 的核心**，形成一个 `API Call → Tool Execution → API Call` 的循环：

```
            ┌──────────────────────────────────────────┐
            │                                          │
            ▼                                          │
     ┌─────────────┐     ┌─────────────┐     ┌─────────┴───────┐
     │ Claude API  │────>│ Tool Use?   │────>│ Execute Tools   │
     │ Call        │     │             │ Yes │ Collect Results │
     └─────────────┘     └──────┬──────┘     └─────────────────┘
                                │ No
                                ▼
                         ┌─────────────┐
                         │ Return to   │
                         │ User        │
                         └─────────────┘
```

这个循环会一直持续，直到模型返回 `stop_reason: "end_turn"`（表示任务完成）或达到最大轮次限制。

## 3. Agent Loop 核心机制

### 3.1 什么是 Agent Loop？

Agent Loop 是 Agent 系统的核心，它实现了 **"思考-行动-观察"** 的循环：

```
┌─────────────────────────────────────────────────────────────────────┐
│                           Agent Loop                                │
│                                                                     │
│    ┌──────────┐    ┌──────────┐    ┌──────────┐                     │
│    │  Think   │───>│   Act    │───>│ Observe  │───┐                 │
│    └──────────┘    └──────────┘    └──────────┘   │                 │
│         ^                                         │                 │
│         └─────────────────────────────────────────┘                 │
│                                                                     │
│    Think:   Analyze user request, plan next step                    │
│    Act:     Call tools (Read, Edit, Bash, Task...)                  │
│    Observe: Get tool results, integrate into context                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 循环终止条件

Agent Loop 在以下情况下终止：

| 条件           | 说明                       |
| -------------- | -------------------------- |
| `end_turn`     | 模型主动结束（任务完成）   |
| `max_tokens`   | 达到输出 token 上限        |
| `max_turns`    | 达到最大轮次限制（可配置） |
| User Interrupt | 用户手动中断（Ctrl+C）     |
| Error          | 发生不可恢复的错误         |

### 3.3 Turn 的定义

一个 "turn" 是一次完整的 API round-trip：

```
Turn 1: User Message → API Call → Response (with Tool Use)
Turn 2: Tool Results → API Call → Response (with Tool Use)
Turn 3: Tool Results → API Call → Response (end_turn)
```

对于复杂任务，一次用户请求可能需要 10-50 个 turns。

### 4.2 工具调用格式

工具调用遵循 Anthropic 的 Tool Use 协议：

```json
// API 响应中的 Tool Use Block
{
  "type": "tool_use",
  "id": "toolu_01ABC123",
  "name": "Read",
  "input": {
    "file_path": "/path/to/file.ts"
  }
}

// 工具执行后返回 Tool Result
{
  "type": "tool_result",
  "tool_use_id": "toolu_01ABC123",
  "content": "文件内容..."
}
```

### 4.3 并行工具调用

Claude Code 支持在单次响应中调用多个独立工具：

```
┌───────────────────────────────────────────────────────────────┐
│                      Single API Response                      │
│                                                               │
│  Tool Use 1: Read("/src/a.ts")  ─┐                            │
│  Tool Use 2: Read("/src/b.ts")  ─┼─> Parallel -> Collect      │
│  Tool Use 3: Glob("**/*.md")    ─┘                            │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

**并行执行条件**：
- 工具之间无数据依赖
- 系统提示词明确指示并行执行

**串行执行场景**：
- 后续工具依赖前序工具的结果
- 例如：先 Read 文件，再基于内容 Edit

### 4.4 关键工具详解

#### Task 工具（启动子 Agent）

```typescript
interface ITaskInput {
  description: string;       // 3-5 词简短描述
  prompt: string;            // 详细任务描述
  subagent_type: string;     // Agent 类型
  model?: "sonnet"|"opus"|"haiku";  // 可选模型
  resume?: string;           // 恢复之前的 Agent
  run_in_background?: boolean;  // 后台运行
  max_turns?: number;        // 最大轮次
}
```

#### Bash 工具（命令执行）

```typescript
interface IBashInput {
  command: string;           // 要执行的命令
  timeout?: number;          // 超时（最大 600000ms）
  description?: string;      // 命令描述
  run_in_background?: boolean;  // 后台运行
}
```

#### Edit 工具（精确编辑）

```typescript
interface IEditInput {
  file_path: string;         // 绝对路径
  old_string: string;        // 要替换的文本（必须唯一）
  new_string: string;        // 替换后的文本
  replace_all?: boolean;     // 全局替换
}
```

## 6. 子 Agent 架构

### 6.1 子 Agent 类型

Claude Code 通过 Task 工具启动专门化的子 Agent：

| Agent 类型         | 默认模型 | 工具集                              | 用途             | 只读 |
| ------------------ | -------- | ----------------------------------- | ---------------- | ---- |
| `Bash`             | inherit  | Bash                                | 命令执行、Git    | ❌   |
| `general-purpose`  | inherit  | All (*)                             | 代码搜索、研究   | ❌   |
| `Explore`          | haiku    | All except Task/Edit/Write          | 快速代码库探索   | ✅   |
| `Plan`             | inherit  | All except Task/Edit/Write          | 架构规划         | ✅   |
| `coder`            | inherit  | All                                 | 代码实现         | ❌   |
| `repair`           | inherit  | All                                 | 迭代修复         | ❌   |
| `claude-code-guide`| haiku    | Glob/Grep/Read/WebFetch/WebSearch   | API/SDK 指南     | ✅   |

### 6.2 子 Agent 工作流

```
┌───────────────────────────────────────────────────────────────────┐
│                    Sub-Agent Launch Flow                          │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│  Main Agent                                                       │
│      |                                                            │
│      | Task({ subagent_type: "Explore", prompt: "..." })          │
│      v                                                            │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │ Sub-Agent Initialization                                    │  │
│  │ * Inherit/select model                                      │  │
│  │ * Configure available tools                                 │  │
│  │ * Inject specialized system prompt                          │  │
│  └─────────────────────────────────────────────────────────────┘  │
│      |                                                            │
│      v                                                            │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │ Sub-Agent Loop                                              │  │
│  │ * Independent Think-Act-Observe cycle                       │  │
│  │ * Uses restricted tool set                                  │  │
│  │ * Follows specialized instructions                          │  │
│  └─────────────────────────────────────────────────────────────┘  │
│      |                                                            │
│      | Return result                                              │
│      v                                                            │
│  Main Agent continues                                             │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

### 6.3 后台 Agent

子 Agent 可以在后台运行：

```typescript
Task({
  subagent_type: "coder",
  prompt: "实现功能 X",
  run_in_background: true  // 后台运行
})
// 返回 output_file 路径
// 主 Agent 可继续其他工作
// 稍后通过 TaskOutput 或 Read 获取结果
```

## 7. 系统提示词动态组合

### 7.1 组合策略

系统提示词不是静态的，而是根据上下文动态组合：

```
┌───────────────────────────────────────────────────────────────────┐
│                  System Prompt Composition                        │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │ Base Part (always included)                                 │  │
│  │ * Identity: "You are Claude Code..."                        │  │
```

## 8. 关键设计决策

### 8.1 为什么使用 Agent Loop？

| 设计决策                   | 原因                                         |
| -------------------------- | -------------------------------------------- |
| 循环而非单次              | 复杂任务需要多步骤，无法一次完成              |
| LLM 驱动决策              | 让模型决定下一步，而非硬编码流程              |
| Tool Use 协议             | 标准化工具调用，支持并行和异步                |
| 可中断                    | 用户可随时介入，保持控制权                    |

### 8.2 为什么使用子 Agent？

| 设计决策                   | 原因                                         |
| -------------------------- | -------------------------------------------- |
| 专门化                    | 不同任务需要不同能力集                        |
| 隔离                      | 子 Agent 有独立上下文，不污染主 Agent         |
| 成本优化                  | 只读任务用 Haiku，降低成本                    |
| 并行性                    | 多个子 Agent 可并行执行                       |

### 8.3 为什么动态组合系统提示词？

| 设计决策                   | 原因                                         |
| -------------------------- | -------------------------------------------- |
| 减少 token 消耗           | 只注入当前需要的指令                          |
| 适应性                    | 根据用户订阅、环境、模式调整能力              |
| 可扩展性                  | 新功能只需添加条件注入模块                    |
| 上下文相关性              | 避免不相关指令干扰模型                        |

### 8.4 关键性能优化

```
┌───────────────────────────────────────────────────────────────────┐
│                   Performance Optimization                        │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│  1. Parallel Tool Calls                                           │
│     * Execute independent tools simultaneously                    │
│     * Reduce round-trips                                          │
│                                                                   │
│  2. Specialized Tools > Bash                                      │
│     * Read > cat, Edit > sed, Glob > find                         │
│     * Specialized tools have optimized paths & security checks    │
│                                                                   │
│  3. Background Agents                                             │
│     * Long-running tasks don't block main Agent                   │
│     * Retrieve results via TaskOutput asynchronously              │
│                                                                   │
│  4. Context Compression                                           │
│     * Incremental conversation summary                            │
│     * Auto-compress old messages when limit exceeded              │
│                                                                   │
│  5. Model Tiering                                                 │
│     * Haiku for exploration tasks (fast, cheap)                   │
│     * Opus for complex implementation (powerful, expensive)       │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

```
│    │   ┌───────────────────────────────┐     │                    │
│    │   │     Claude API Call           │     │                    │
```

**Key Takeaways**:

1. **Agent Loop is the Core** - Handles complex tasks through "Think-Act-Observe" cycle
2. **Tools are Agent's Limbs** - 19 tools enable file R/W, command execution, code search, web access
3. **Sub-Agents Enable Divide-and-Conquer** - Complex tasks are delegated to specialized sub-agents
4. **System Prompt is the Brain** - Dynamically composed prompts define Agent capabilities and behavior
5. **Message Processing Ensures Continuity** - Pre/post-processing maintains session continuity and context
